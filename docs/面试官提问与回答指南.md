## 1. 项目架构与技术栈

### Q1.1: 请介绍一下这个项目的整体架构设计？

**回答：**

这是一个基于Spring Boot 3.x的AI面试平台，采用分层架构设计：

**架构层次：**
- **Controller层**：处理HTTP请求，包括简历上传、动态面试、语音识别等接口
- **Service层**：核心业务逻辑，包括简历ETL、动态提问、RAG评估、语音识别等
- **DAO层**：数据访问层，使用MyBatis Plus进行数据库操作
- **POJO层**：实体类和VO对象
- **Common层**：公共工具类和枚举

**技术栈：**
- **后端框架**：Spring Boot 3.3.4 + Spring AI 1.0.0
- **数据库**：MySQL 8.0 + MyBatis Plus 3.5.7
- **缓存**：Redis（存储简历、对话上下文、向量数据）
- **消息队列**：RabbitMQ（异步任务处理）
- **AI模型**：阿里云DashScope（通义千问Qwen）、智谱AI
- **文档解析**：Apache Tika（通过Spring AI TikaDocumentReader）
- **并发处理**：Java 21虚拟线程 + CompletableFuture
- **流式传输**：SSE（Server-Sent Events）

**核心模块：**
1. **简历处理模块**：ETL清洗、隐私脱敏、格式规范化
2. **动态面试模块**：基于简历/JD的智能提问、去重机制
3. **RAG评估模块**：向量检索、评分标准注入、智能评估
4. **语音识别模块**：阿里云ASR、实时转写
5. **异步任务模块**：RabbitMQ异步化、限流、重试、死信队列

## 2. RAG检索增强生成

### Q2.1: 请详细解释一下RAG的工作原理，以及你在项目中是如何实现的？

**回答：**

**RAG（Retrieval-Augmented Generation）工作原理：**

RAG是一种结合检索和生成的技术，通过检索相关文档来增强LLM的生成能力。

**工作流程：**
1. **文档向量化**：将评分标准、课程资料等文档切分为chunks，通过Embedding模型转换为向量
2. **向量存储**：将向量存储到Redis向量库中
3. **查询向量化**：将用户问题转换为向量
4. **相似度检索**：在向量库中检索topK个最相似的文档chunks
5. **上下文注入**：将检索到的文档作为上下文注入到Prompt中
6. **增强生成**：LLM基于检索到的上下文生成更准确的回答

**项目实现：**

```java
// 1. 文档向量化入库
VectorStoreIngestionService.ingestDocuments(documents);

// 2. RAG检索
private String retrieveScoringCriteria(String questionText) {
    SearchRequest request = SearchRequest.builder()
        .query(questionText)
        .topK(3)  // 检索top3最相关的文档
        .filterExpression("doc_type == 'scoring_criteria'")  // 过滤评分标准
        .build();
    
    List<Document> docs = vectorStore.similaritySearch(request);
    return docs.stream()
        .map(Document::getText)
        .collect(Collectors.joining("\n"));
}

// 3. 注入Prompt
Map<String, Object> variables = Map.of(
    "question", questionText,
    "candidateAnswer", answerContent,
    "criteria", criteria  // RAG检索到的评分标准
);
```

**优势：**
- **减少幻觉**：基于真实文档生成，避免LLM编造信息
- **个性化**：根据问题动态检索相关标准
- **可追溯**：可以查看检索到的文档来源

### Q2.2: 为什么选择Redis作为向量数据库？它的优缺点是什么？

**回答：**

**选择Redis的原因：**

1. **技术栈统一**：项目已经使用Redis做缓存，无需引入新的中间件
2. **部署简单**：Redis部署和维护成本低
3. **性能优秀**：内存存储，检索速度快
4. **Spring AI支持**：Spring AI提供了Redis向量库的集成

**优点：**
- **低延迟**：内存存储，毫秒级检索
- **易于扩展**：支持Redis Cluster水平扩展
- **成本低**：相比Pinecone、Weaviate等专业向量数据库，成本更低
- **功能丰富**：除了向量检索，还可以做缓存、消息队列等

**缺点：**
- **容量限制**：内存容量有限，不适合超大规模向量库
- **持久化**：需要配置RDB/AOF持久化，否则重启会丢失数据
- **向量检索性能**：相比Milvus、Qdrant等专业向量数据库，性能略逊
- **功能单一**：没有高级功能如混合检索、元数据过滤等

**适用场景：**
- 中小规模向量库（百万级向量以内）
- 对延迟要求高的场景
- 预算有限的项目

**如果向量库规模很大（千万级以上），建议迁移到Milvus或Qdrant。**

### Q2.3: 如何评估RAG系统的检索质量？你使用了哪些指标？

**回答：**

**评估指标：**

1. **命中率（Hit Rate）**：
   - 定义：topK结果中是否包含至少一个相关文档
   - 公式：`命中率 = 命中查询数 / 总查询数`
   - 意义：衡量检索系统能否找到相关文档

2. **精确率（Precision）**：
   - 定义：检索到的相关文档数 / 检索到的总文档数
   - 公式：`P = |相关文档 ∩ 检索文档| / |检索文档|`
   - 意义：衡量检索结果的相关性

3. **召回率（Recall）**：
   - 定义：检索到的相关文档数 / 总相关文档数
   - 公式：`R = |相关文档 ∩ 检索文档| / |总相关文档|`
   - 意义：衡量检索系统的覆盖度

4. **F1分数**：
   - 定义：精确率和召回率的调和平均
   - 公式：`F1 = 2 * P * R / (P + R)`
   - 意义：综合衡量精确率和召回率

5. **MRR（Mean Reciprocal Rank）**：
   - 定义：第一个相关文档排名的倒数
   - 公式：`MRR = 1 / rank(第一个相关文档)`
   - 意义：衡量相关文档的排名位置

6. **NDCG（归一化折扣累积增益）**：
   - 定义：考虑排名位置的累积增益
   - 公式：`NDCG = DCG / IDCG`
   - 意义：衡量检索结果的排序质量

**项目实现：**

**3. 改进文档切分策略（chunk size、overlap）：**

**当前实现（项目中没有明确的chunk切分）：**
```java
// 当前是直接使用整个文档作为chunk
Document doc = new Document(question, content, metadata);
vectorStore.add(doc);  // 整个文档作为一个chunk
```

**优化方案：**

**a) 实现文档切分：**
```java
@Service
public class DocumentChunkingService {
    
    // 配置参数
    private static final int CHUNK_SIZE = 500;      // 每个chunk的token数
    private static final int CHUNK_OVERLAP = 50;     // chunk之间的重叠token数
    
    public List<Document> splitDocument(String content, Map<String, Object> metadata) {
        List<Document> chunks = new ArrayList<>();
        
        // 1. 按段落切分（保留语义完整性）
        String[] paragraphs = content.split("\n\n");
        
        // 2. 合并段落，直到达到chunk_size
        StringBuilder currentChunk = new StringBuilder();
        int currentSize = 0;
        
        for (String paragraph : paragraphs) {
            int paragraphSize = estimateTokenCount(paragraph);
            
            if (currentSize + paragraphSize > CHUNK_SIZE && currentChunk.length() > 0) {
                // 保存当前chunk
                chunks.add(createChunk(currentChunk.toString(), metadata, chunks.size()));
                
                // 创建新chunk，保留重叠部分
                String overlap = extractOverlap(currentChunk.toString(), CHUNK_OVERLAP);
                currentChunk = new StringBuilder(overlap + "\n\n" + paragraph);
                currentSize = estimateTokenCount(currentChunk.toString());
            } else {
                currentChunk.append(paragraph).append("\n\n");
                currentSize += paragraphSize;
            }
        }
        
        // 保存最后一个chunk
        if (currentChunk.length() > 0) {
            chunks.add(createChunk(currentChunk.toString(), metadata, chunks.size()));
        }
        
        return chunks;
    }
    
    private Document createChunk(String text, Map<String, Object> metadata, int chunkIndex) {
        Map<String, Object> chunkMetadata = new HashMap<>(metadata);
        chunkMetadata.put("chunk_index", chunkIndex);
        chunkMetadata.put("chunk_size", text.length());
        return new Document(text, chunkMetadata);
    }
    
    private String extractOverlap(String text, int overlapTokens) {
        // 从文本末尾提取overlap部分
        int estimatedChars = overlapTokens * 4;  // 粗略估算：1 token ≈ 4字符
        if (text.length() <= estimatedChars) {
            return text;
        }
        return text.substring(text.length() - estimatedChars);
    }
    
    private int estimateTokenCount(String text) {
        // 粗略估算：中文1.5字符/token，英文4字符/token
        int chineseChars = text.replaceAll("[^\\u4e00-\\u9fa5]", "").length();
        int otherChars = text.length() - chineseChars;
        return (int)(chineseChars / 1.5 + otherChars / 4);
    }
}
```

**4. 添加重排序（reranking）机制：**

**问题：** 向量相似度检索可能不够准确，需要二次排序

**优化方案：**

**a) 使用重排序模型：**
```java
@Service
public class RerankingService {
    
    // 使用专门的重排序模型（如BGE Reranker）
    public List<Document> rerank(
        List<Document> candidates, 
        String query, 
        int topK
    ) {
        // 1. 使用重排序模型计算query和每个doc的相关性分数
        List<ScoredDocument> scoredDocs = candidates.stream()
            .map(doc -> {
                double score = rerankModel.score(query, doc.getText());
                return new ScoredDocument(doc, score);
            })
            .sorted(Comparator.comparing(ScoredDocument::getScore).reversed())
            .limit(topK)
            .collect(Collectors.toList());
        
        return scoredDocs.stream()
            .map(ScoredDocument::getDocument)
            .collect(Collectors.toList());
    }
}
```

**b) 基于关键词匹配的重排序：**

public List<Document> rerankByKeywords(
    List<Document> candidates, 
    String query
) {
    // 提取查询关键词
    Set<String> queryKeywords = extractKeywords(query);
    
    return candidates.stream()
        .map(doc -> {
            // 计算关键词匹配度
            Set<String> docKeywords = extractKeywords(doc.getText());
            double keywordScore = calculateKeywordOverlap(queryKeywords, docKeywords);
            
            // 结合向量相似度分数
            double finalScore = doc.getMetadata().get("similarity_score") * 0.7 
                              + keywordScore * 0.3;
            
            return new ScoredDocument(doc, finalScore);
        })
        .sorted(Comparator.comparing(ScoredDocument::getScore).reversed())
        .collect(Collectors.toList());
}
```

**c) 多策略融合重排序：**
```java
public List<Document> hybridRerank(
    List<Document> candidates, 
    String query
) {
    return candidates.stream()
        .map(doc -> {
            // 1. 向量相似度分数（已有）
            double vectorScore = (Double) doc.getMetadata().get("similarity_score");
            
            // 2. 关键词匹配分数
            double keywordScore = calculateKeywordScore(query, doc.getText());
            
            // 3. 位置分数（文档在原始文档中的位置）
            double positionScore = calculatePositionScore(doc);
            
            // 4. 融合分数
            double finalScore = vectorScore * 0.5 
                              + keywordScore * 0.3 
                              + positionScore * 0.2;
            
            return new ScoredDocument(doc, finalScore);
        })
        .sorted(Comparator.comparing(ScoredDocument::getScore).reversed())
        .collect(Collectors.toList());
}
```

private List<Document> retrieveCourseDocuments(String queryText) {
    // 策略1：使用原始查询文本检索
    SearchRequest courseRequest = SearchRequest.builder()
        .query(queryText)  // 薄弱点文本
        .topK(5)
        .filterExpression("doc_type == 'course'")  // 只检索课程文档
        .build();
    List<Document> courseDocs = vectorStore.similaritySearch(courseRequest);
    
    if (courseDocs != null && !courseDocs.isEmpty()) {
        return courseDocs;
    }
    
    // 策略2：提取关键词重新检索
    String keywords = extractKeywords(queryText);
    if (keywords != null && !keywords.isEmpty()) {
        SearchRequest keywordRequest = SearchRequest.builder()
            .query(keywords)
            .topK(5)
            .filterExpression("doc_type == 'course'")
            .build();
        courseDocs = vectorStore.similaritySearch(keywordRequest);
        if (courseDocs != null && !courseDocs.isEmpty()) {
            return courseDocs;
        }
    }
    
    // 策略3：宽泛查询（不限制文档类型）
    SearchRequest broadRequest = SearchRequest.builder()
        .query(keywords != null ? keywords : queryText)
        .topK(3)
        .build();
    List<Document> broadDocs = vectorStore.similaritySearch(broadRequest);
    
    // 过滤出可能是课程的内容
    return broadDocs.stream()
        .filter(doc -> {
            String text = doc.getText().toLowerCase();
            return text.contains("课程") || text.contains("学习") || 
                   text.contains("教程") || text.contains("培训");
        })
        .limit(3)
        .toList();
}
```

**5. AI生成个性化推荐：**

```java
public void generateCourseRecommendation(String recordId, InterviewEvaluation evaluation) {
    // 1. 提取薄弱点
    List<String> weaknesses = evaluation.getWeaknesses();
    if (weaknesses == null || weaknesses.isEmpty()) {
        log.warn("【推荐课程】无薄弱点，跳过推荐");
        return;
    }
    
    // 2. 为每个薄弱点检索相关课程
    StringBuilder courseContext = new StringBuilder();
    for (String weakness : weaknesses) {
        List<Document> courseDocs = retrieveCourseDocuments(weakness);
        if (!courseDocs.isEmpty()) {
            courseContext.append("薄弱点：").append(weakness).append("\n");
            courseContext.append("相关课程：\n");
            for (Document doc : courseDocs) {
                courseContext.append("- ").append(doc.getText()).append("\n");
            }
            courseContext.append("\n");
        }
    }
    
    // 3. 构建Prompt
    Map<String, Object> variables = Map.of(
        "weaknesses", String.join("\n", weaknesses),
        "course_context", courseContext.toString(),
        "overall_evaluation", evaluation.getOverallEvaluation()
    );
    
    Prompt prompt = courseRecommendationTemplate.create(variables);
    
    // 4. 调用AI生成推荐
    String recommendationJson = aiModelWrapper.callAiModel(
        qwenModel, 
        prompt, 
        "课程推荐"
    );
    
    // 5. 解析并保存
    CourseRecommendation recommendation = parseRecommendation(recommendationJson);
    saveRecommendation(recordId, recommendation);
}
```

**为什么要清洗？**

1. **隐私保护**：
   - 避免手机号、邮箱、身份证等敏感信息泄露
   - 符合数据保护法规（GDPR、个人信息保护法）

**Token计算方法详解：**

**1. 基本估算方法：**

**英文文本：**
```
Token数 ≈ 字符数 / 4

示例：
文本："Hello, how are you?" (20字符)
Token数 ≈ 20 / 4 = 5 tokens
实际：约6 tokens（包含标点）
```

**中文文本：**
```
Token数 ≈ 字符数 / 1.5

示例：
文本："你好，今天天气怎么样？" (11字符)
Token数 ≈ 11 / 1.5 = 7.3 ≈ 7-8 tokens
实际：约11 tokens（中文通常1字符=1token）
```

**混合文本（中英文）：**
```
分别计算中英文部分，然后相加

示例：
文本："使用Spring Boot开发" (10字符：2中文 + 8英文)
中文部分：2字符 / 1.5 = 1.3 tokens
英文部分：8字符 / 4 = 2 tokens
总计：约3-4 tokens
```

```java
public String cleanText(String content, List<DocumentTransformer> transformers) {
    if (content == null || content.isEmpty()) {
        return content;
    }
    
    // 1. 创建初始Document
    Document document = new Document(content);
    
    // 2. 链式应用所有转换器
    for (DocumentTransformer transformer : transformers) {
        List<Document> transformed = transformer.apply(List.of(document));
        if (transformed != null && !transformed.isEmpty()) {
            document = transformed.get(0);  // 取第一个（通常只有一个）
        }
    }
    
    // 3. 返回最终文本
    return document.getText();
}

    createFormatNormalizerTransformer()     // 步骤2：规范化格式

### Q5.1: 请详细说明CompletableFuture + 虚拟线程的并发优化方案，以及性能提升的具体数据？

**回答：**

**优化前（串行处理）：**
```java
// 串行评估所有题目
for (AnswerBO answer : allQuestions) {
    String analysis = analyzeSingleQuestion(answer);
    results.add(analysis);
}
// 耗时：51秒（10道题，每题约5秒）
```

**优化后（并行处理）：**
```java
// 使用CompletableFuture + 虚拟线程并行评估
List<CompletableFuture<String>> analysisFutures = allQuestions.stream()
    .map(answer -> CompletableFuture.supplyAsync(() -> {
        return analyzeSingleQuestion(answer);
    }, executor))  // executor使用虚拟线程
    .toList();

// 等待所有任务完成
CompletableFuture.allOf(analysisFutures.toArray(new CompletableFuture[0])).join();

// 收集结果
String result = analysisFutures.stream()
    .map(CompletableFuture::join)
    .collect(Collectors.joining());
```

**虚拟线程配置：**
```java
@Configuration
public class ThreadPoolConfig {
    @Bean
    public Executor virtualThreadExecutor() {
        // Java 21虚拟线程
        return Executors.newVirtualThreadPerTaskExecutor();
    }
}
```

**性能数据：**

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 单用户评估耗时 | 51秒 | 9秒 | **82%** |
| 500并发请求完成时间 | - | 65秒 | - |
| 失败率 | - | 0% | - |
| 吞吐量 | - | 显著提升 | - |

**为什么选择虚拟线程？**

1. **轻量级**：
   - 传统线程：1MB栈空间，创建成本高
   - 虚拟线程：几KB内存，可以创建百万级线程

2. **高并发**：
   - 传统线程池：受限于线程数（如100个线程）
   - 虚拟线程：可以创建大量线程，适合IO密集型任务

3. **简化代码**：
   - 无需手动管理线程池大小
   - 自动调度，由JVM管理

**适用场景：**
- **IO密集型任务**：如AI API调用、数据库查询、HTTP请求
- **高并发场景**：需要处理大量并发请求
- **阻塞操作**：虚拟线程在阻塞时会自动释放CPU，让其他线程执行

**注意事项：**
- 不适合CPU密集型任务（计算密集）
- Java 21+才支持虚拟线程

### Q5.3: CompletableFuture的详细原理和运用场景？

**回答：**

**CompletableFuture核心原理：**

**1. 什么是CompletableFuture？**

`CompletableFuture`是Java 8引入的异步编程工具，实现了`Future`和`CompletionStage`接口。

**核心特点：**
- **异步执行**：任务在后台线程执行，不阻塞主线程
- **链式调用**：支持多个异步任务的组合和依赖
- **异常处理**：提供完善的异常处理机制
- **结果组合**：可以组合多个Future的结果

**2. 核心方法分类：**

**a) 创建CompletableFuture：**
```java
// 1. 使用supplyAsync（有返回值）
CompletableFuture<String> future1 = CompletableFuture.supplyAsync(() -> {
    return "Hello";
}, executor);

// 2. 使用runAsync（无返回值）
CompletableFuture<Void> future2 = CompletableFuture.runAsync(() -> {
    System.out.println("Task running");
}, executor);

// 3. 使用completedFuture（已完成）
CompletableFuture<String> future3 = CompletableFuture.completedFuture("Done");
```

**b) 获取结果：**
```java
// 阻塞等待结果
String result = future1.get();  // 可能抛出InterruptedException, ExecutionException

// 带超时的获取
String result = future1.get(5, TimeUnit.SECONDS);  // 超时抛出TimeoutException

// 非阻塞获取（立即返回，可能为null）
String result = future1.getNow("default");  // 如果未完成，返回默认值

// 等待完成（不获取结果）
future1.join();  // 类似get()，但抛出未检查异常
```

**c) 链式调用（组合操作）：**

**thenApply（转换结果）：**
```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> "Hello")
    .thenApply(s -> s + " World")      // 同步转换
    .thenApply(String::toUpperCase);   // 继续转换

// 结果："HELLO WORLD"
```

**thenCompose（扁平化，避免嵌套）：**
```java
// 避免嵌套CompletableFuture<CompletableFuture<String>>
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> "Hello")
    .thenCompose(s -> CompletableFuture.supplyAsync(() -> s + " World"));
    // 返回CompletableFuture<String>，而不是CompletableFuture<CompletableFuture<String>>

// 结果："Hello World"
```

**thenCombine（组合两个Future的结果）：**
```java
CompletableFuture<String> future1 = CompletableFuture.supplyAsync(() -> "Hello");
CompletableFuture<String> future2 = CompletableFuture.supplyAsync(() -> "World");

CompletableFuture<String> combined = future1.thenCombine(future2, (s1, s2) -> {
    return s1 + " " + s2;
});

// 结果："Hello World"
```

**allOf（等待所有Future完成）：**
```java
List<CompletableFuture<String>> futures = List.of(
    CompletableFuture.supplyAsync(() -> "Task1"),
    CompletableFuture.supplyAsync(() -> "Task2"),
    CompletableFuture.supplyAsync(() -> "Task3")
);

CompletableFuture<Void> allFutures = CompletableFuture.allOf(
    futures.toArray(new CompletableFuture[0])
);

// 等待所有完成
allFutures.join();

// 收集结果
List<String> results = futures.stream()
    .map(CompletableFuture::join)
    .toList();
```

**anyOf（任意一个完成即可）：**
```java
CompletableFuture<String> future1 = CompletableFuture.supplyAsync(() -> {
    Thread.sleep(5000);
    return "Slow Task";
});

CompletableFuture<String> future2 = CompletableFuture.supplyAsync(() -> {
    Thread.sleep(1000);
    return "Fast Task";
});

CompletableFuture<Object> anyFuture = CompletableFuture.anyOf(future1, future2);
String result = (String) anyFuture.join();

// 结果："Fast Task"（最快完成的）
```

**d) 异常处理：**
```java
CompletableFuture<String> future = CompletableFuture
    .supplyAsync(() -> {
        if (Math.random() > 0.5) {
            throw new RuntimeException("Error");
        }
        return "Success";
    })
    .exceptionally(ex -> {
        // 异常处理，返回默认值
        log.error("任务失败", ex);
        return "Default Value";
    })
    .handle((result, ex) -> {
        // 同时处理正常结果和异常
        if (ex != null) {
            return "Error occurred";
        }
        return result;
    });
```

**6. 最佳实践：**

### Q6.1: 请详细说明RabbitMQ的异步架构设计，包括死信队列和幂等性保障？

**回答：**

**异步架构设计：**

**1. 消息发送（Controller层）：**
```java
@PostMapping("/submit")
public GraceJSONResult submitAnswers(@RequestBody SubmitAnswerBO submitAnswerBO) {

```

**2. 消息消费（Listener层）：**

@RabbitListener(queues = RabbitMQConfig.QUEUE_INTERVIEW)
public void handleInterviewAnalysis(SubmitAnswerBO submitAnswerBO) {

}
```

**3. 死信队列（DLQ）配置：**
```java
@Bean
public Queue queueInterview() {
    Map<String, Object> args = new HashMap<>();
    // 绑定死信交换机

```

**死信队列的作用：**
1. **失败隔离**：失败消息不会影响正常消息处理
2. **问题排查**：可以查看DLQ中的消息，分析失败原因
3. **人工处理**：对于无法自动恢复的错误，可以人工处理
4. **监控告警**：DLQ中有消息时，可以触发告警

**4. 幂等性保障：**

**问题场景：**
- 消息重复消费（网络重传、消费者重启等）
- 导致重复分析，浪费资源

**解决方案：**
```java
// 使用Redis记录已处理的任务ID
String taskId = generateTaskId(submitAnswerBO);
String key = "interview:task:" + taskId;

// 使用SETNX（SET if Not eXists）实现分布式锁
Boolean success = stringRedisTemplate.opsForValue()
    .setIfAbsent(key, "processing", 1, TimeUnit.HOURS);

if (!success) {
    log.warn("任务已处理，跳过: {}", taskId);
    return;  // 幂等：已处理，直接返回
}

try {
    // 执行分析
    chatGLMService.analyzeInterview(submitAnswerBO);
    // 标记为已完成
    stringRedisTemplate.opsForValue().set(key, "completed", 24, TimeUnit.HOURS);
} catch (Exception e) {
    // 失败时删除key，允许重试
    stringRedisTemplate.delete(key);
    throw e;
}
```

**幂等性保障机制：**
1. **唯一任务ID**：基于candidateId + jobId + timestamp生成
2. **Redis分布式锁**：使用SETNX实现
3. **状态标记**：processing → completed
4. **失败重试**：失败时删除key，允许重新处理

### Q6.2: 如何实现限流和自动重试？RateLimiter的工作原理是什么？

**回答：**

**限流实现（RateLimiter）：**

```java
@Service
public class AiModelWrapperService {
    // 使用Guava RateLimiter，限制2次/秒
    private final RateLimiter rateLimiter = RateLimiter.create(2.0);
    
    public String callAiModel(ChatModel model, Prompt prompt, String operation) {
        // 获取令牌，如果没有可用令牌则阻塞等待
        rateLimiter.acquire();
        
        // 调用AI模型
        return model.call(prompt).getResult().getOutput().getText();
    }
}
```

**RateLimiter工作原理：**

1. **令牌桶算法**：
   - 桶容量：2个令牌
   - 生成速率：2个令牌/秒
   - 每次调用消耗1个令牌

2. **工作流程**：
   ```
   时间0s：桶中有2个令牌
   调用1：消耗1个令牌，剩余1个
   调用2：消耗1个令牌，剩余0个
   调用3：等待0.5秒，生成1个令牌，消耗1个令牌
   ```

3. **特点**：
   - **平滑限流**：不会突然拒绝请求，而是平滑控制速率
   - **允许突发**：如果桶中有令牌，可以立即处理
   - **阻塞等待**：没有令牌时，会阻塞等待，而不是拒绝

**自动重试实现：**

```java
@Configuration
public class RetryConfig {
    @Bean
    public RetryTemplate retryTemplate() {
        RetryTemplate retryTemplate = new RetryTemplate();
        
        // 重试策略：最多重试3次
        SimpleRetryPolicy retryPolicy = new SimpleRetryPolicy();
        retryPolicy.setMaxAttempts(3);
        retryTemplate.setRetryPolicy(retryPolicy);
        
        // 退避策略：指数退避
        ExponentialBackOffPolicy backOffPolicy = new ExponentialBackOffPolicy();
        backOffPolicy.setInitialInterval(1000);  // 首次重试等待1秒
        backOffPolicy.setMultiplier(2.0);        // 每次重试等待时间翻倍
        retryTemplate.setBackOffPolicy(backOffPolicy);
        
        return retryTemplate;
    }
}

// 使用
public String callAiModelWithRetry(ChatModel model, Prompt prompt) {
    return retryTemplate.execute(context -> {
        try {
            return model.call(prompt).getResult().getOutput().getText();
        } catch (NonTransientAiException e) {
            // 可重试异常
            throw e;
        } catch (Exception e) {
            // 不可重试异常（如参数错误）
            throw new RuntimeException("不可重试异常", e);
        }
    });
}
```

**重试策略：**
- **最大重试次数**：3次
- **退避策略**：指数退避（1秒 → 2秒 → 4秒）
- **重试条件**：只对`NonTransientAiException`（网络错误、超时等）重试
- **不重试**：参数错误、认证失败等不可恢复的错误

**限流 + 重试的配合：**
1. **限流保护**：防止API被刷，保护QPS配额
2. **重试保障**：网络抖动时自动重试，提高成功率
3. **死信队列**：重试3次仍失败，发送到DLQ，人工处理

## 7. 流式响应与SSE

### Q7.1: 什么是SSE？为什么选择SSE而不是WebSocket？

**回答：**

**SSE（Server-Sent Events）：**

SSE是一种服务器向客户端推送数据的技术，基于HTTP协议。

**特点：**
- **单向通信**：服务器 → 客户端
- **基于HTTP**：无需额外协议
- **自动重连**：浏览器自动处理断线重连
- **简单易用**：比WebSocket简单

**项目实现：**

**后端（Spring Boot）：**

        dynamicInterviewService.generateQuestionStream(
            candidateId, lastAnswer, lastQuestion, emitter

    });

// 流式发送
qwenModel.stream(aiPrompt).subscribe(
    response -> {
        String chunk = response.getResult().getOutput().getText();
        emitter.send(SseEmitter.event()
            .name("question")
            .data("{\"content\":\"" + chunk + "\",\"finished\":false}"));
    },
    error -> {
        emitter.completeWithError(error);
    },
    () -> {
        emitter.send(SseEmitter.event()
            .name("question")

    }
);
```

**前端（uni-app）：**

**为什么选择SSE而不是WebSocket？**

| 特性 | SSE | WebSocket |
|------|-----|-----------|
| **通信方向** | 单向（服务器→客户端） | 双向 |
| **协议** | HTTP | 独立协议（ws://） |
| **复杂度** | 简单 | 复杂（需要心跳、重连等） |
| **适用场景** | 服务器推送（如AI流式输出） | 实时双向通信（如聊天） |
| **浏览器支持** | 良好 | 良好 |
| **自动重连** | 是 | 需要手动实现 |

**选择SSE的原因：**
1. **需求匹配**：只需要服务器推送AI生成的内容，不需要客户端向服务器发送数据
2. **实现简单**：SSE实现更简单，代码量少
3. **自动重连**：浏览器自动处理断线重连
4. **HTTP友好**：基于HTTP，易于通过代理和防火墙

**如果未来需要双向通信（如实时聊天），可以考虑升级到WebSocket。**

### Q7.2: 如何处理SSE的跨平台兼容性问题？uni-app在不同平台的实现差异？

**回答：**

**跨平台兼容性问题：**

**1. H5平台：**
- 支持原生`EventSource` API
- 实现简单，直接使用

**2. APP平台（Android/iOS）：**
- 不支持`EventSource`
- 需要使用`XMLHttpRequest`手动解析SSE数据流

**3. 小程序平台：**
- 不支持`EventSource`
- 需要使用`uni.request` + 流式解析

**解决方案（条件编译）：**

```javascript
// #ifdef H5
// H5平台：使用原生EventSource
initSSE() {
    var eventSource = new EventSource(this.sseUrl);
    eventSource.addEventListener('question', (event) => {
        var data = JSON.parse(event.data);
        this.handleSSEData(data);
    });
    eventSource.addEventListener('error', (error) => {
        console.error('SSE错误', error);
        eventSource.close();
    });
}
// #endif

// #ifdef APP-PLUS
// APP平台：使用XMLHttpRequest
initSSE() {
    var xhr = new XMLHttpRequest();
    xhr.open('GET', this.sseUrl, true);
    xhr.setRequestHeader('Accept', 'text/event-stream');
    
    var buffer = '';
    xhr.onreadystatechange = () => {
        if (xhr.readyState === 3 || xhr.readyState === 4) {
            var newData = xhr.responseText.substring(buffer.length);
            buffer = xhr.responseText;
            this.parseSSEChunk(newData);
        }
    };
    xhr.send();
}

parseSSEChunk(chunk) {
    var lines = chunk.split('\n');
    for (var line of lines) {
        if (line.startsWith('data:')) {
            var dataStr = line.substring(5).trim();
            var data = JSON.parse(dataStr);
            this.handleSSEData(data);
        }
    }
}
// #endif

// #ifdef MP-WEIXIN
// 微信小程序：使用uni.request + 流式解析
initSSE() {
    uni.request({
        url: this.sseUrl,
        method: 'GET',
        responseType: 'arraybuffer',
        success: (res) => {
            // 解析ArrayBuffer为文本
            var text = this.arrayBufferToString(res.data);
            this.parseSSEChunk(text);
        }
    });
}
// #endif
```

**SSE数据格式解析：**

SSE数据格式：
```
event: question
data: {"content":"你好","finished":false}

event: question
data: {"content":"请问","finished":false}

event: question
data: {"finished":true}
```

**解析逻辑：**
```javascript
parseSSEChunk(chunk) {
    var lines = chunk.split('\n');
    var currentEvent = null;
    var currentData = '';
    
    for (var line of lines) {
        if (line.startsWith('event:')) {
            currentEvent = line.substring(6).trim();
        } else if (line.startsWith('data:')) {
            currentData = line.substring(5).trim();
            if (currentEvent === 'question') {
                var data = JSON.parse(currentData);
                this.handleSSEData(data);
            }
        } else if (line === '') {
            // 空行表示一个事件结束
            currentEvent = null;
            currentData = '';
        }
    }
}
```

**关键点：**
1. **条件编译**：使用`#ifdef`根据不同平台编译不同代码
2. **数据缓冲**：APP平台需要缓冲数据，因为`XMLHttpRequest`可能分多次返回
3. **错误处理**：不同平台的错误处理方式不同
4. **超时处理**：设置合理的超时时间，避免长时间占用连接

    try {
        // 1. 提取JSON
        String json = extractJson(rawJson);
        
        // 2. 使用BeanOutputConverter转换
        BeanOutputConverter<InterviewEvaluation> converter = 
            new BeanOutputConverter<>(InterviewEvaluation.class);

        log.error("JSON转换失败，使用默认值", e);
        // 返回默认对象

private String extractJson(String text) {
    // 移除Markdown代码块
    text = text.replaceAll("```json\\s*", "")
               .replaceAll("```\\s*", "");
    
    // 提取第一个{}之间的内容
    Pattern pattern = Pattern.compile("\\{.*\\}", Pattern.DOTALL);
    Matcher matcher = pattern.matcher(text);
    if (matcher.find()) {
        return matcher.group();
    }
    
    return text;
}
```

            if (i == maxRetries - 1) {
                log.error("转换失败，已重试{}次", maxRetries, e);
                return createDefaultEvaluation();
            }
            // 可以尝试修复JSON（如添加缺失字段）
            rawJson = tryFixJson(rawJson);
        }
    }
    return createDefaultEvaluation();
}

## 9. 大模型核心知识点

### Q9.1: 什么是LLM？它的核心原理是什么？

**回答：**

**LLM（Large Language Model，大语言模型）：**

LLM是一种基于深度学习的自然语言处理模型，能够理解和生成人类语言。

**核心原理：**

**1. Transformer架构：**
- **自注意力机制（Self-Attention）**：模型可以关注输入序列中的不同位置
- **编码器-解码器结构**：编码器理解输入，解码器生成输出
- **位置编码（Positional Encoding）**：为序列中的每个位置添加位置信息

**2. 预训练（Pre-training）：**
- **无监督学习**：在大规模文本数据上训练
- **任务**：预测下一个词（Next Token Prediction）
- **数据**：互联网文本、书籍、代码等

**3. 微调（Fine-tuning）：**
- **有监督学习**：在特定任务数据上微调
- **任务**：问答、对话、代码生成等
- **方法**：全量微调、LoRA、QLoRA等

**4. 生成过程：**
```
输入："请介绍一下Spring Boot"
↓
Token化：["请", "介绍", "一下", "Spring", "Boot"]
↓
Embedding：转换为向量
↓
Transformer处理：理解语义
↓
输出概率分布：每个可能的下一个词的概率
↓
采样：选择概率最高的词（或使用其他采样策略）
↓
生成："Spring Boot是一个..."
```

**关键技术：**

1. **Token化（Tokenization）**：
   - 将文本切分为Token（词或子词）
   - 中文：按字或词切分
   - 英文：按词或BPE（Byte Pair Encoding）切分

2. **Embedding（嵌入）**：
   - 将Token转换为向量
   - 语义相似的词向量距离近

3. **注意力机制（Attention）**：
   - 计算每个Token对其他Token的注意力权重
   - 重要信息获得更高权重

4. **生成策略**：
   - **贪婪搜索（Greedy）**：选择概率最高的词
   - **采样（Sampling）**：按概率分布采样
   - **Top-K/Top-P**：限制候选词范围

### Q9.3: 什么是Token？如何计算Token数量？

**回答：**

**Token（令牌）：**

Token是LLM处理文本的基本单位，可以是词、子词或字符。

**Token化示例：**

**英文：**
```
文本："Hello, how are you?"
Token：["Hello", ",", " how", " are", " you", "?"]
Token数：6
```

**中文：**
```
文本："你好，今天天气怎么样？"
Token：["你", "好", "，", "今", "天", "天", "气", "怎", "么", "样", "？"]
Token数：11
```

**Token计算：**

**1. 估算方法：**
- **英文**：1 Token ≈ 4个字符
- **中文**：1 Token ≈ 1.5个字符
- **代码**：1 Token ≈ 3-4个字符

**2. 精确计算：**
```java
// 使用模型的Tokenizer
Tokenizer tokenizer = Tokenizer.fromPretrained("qwen-tokenizer");
List<String> tokens = tokenizer.encode(text);
int tokenCount = tokens.size();
```

**3. 在线工具：**
- OpenAI Tokenizer：https://platform.openai.com/tokenizer
- 各AI平台通常提供Token计算API

**Token消耗：**

**输入Token（Input Tokens）：**
- Prompt中的文本
- 上下文信息
- 历史对话

**输出Token（Output Tokens）：**
- LLM生成的文本

**总Token = 输入Token + 输出Token**

**成本计算：**
```
成本 = 输入Token数 × 输入单价 + 输出Token数 × 输出单价

例如（通义千问）：
输入：$0.008 / 1K tokens
输出：$0.008 / 1K tokens

1000输入Token + 500输出Token = 1500 Token
成本 = 1 × $0.008 + 0.5 × $0.008 = $0.012
```

**优化Token消耗：**

1. **文本清洗**：移除冗余信息（如简历ETL）
2. **压缩Prompt**：只保留必要信息
3. **限制输出长度**：设置max_tokens参数
4. **缓存结果**：相同输入不重复调用

### Q9.4: 什么是Temperature、Top-K、Top-P？它们如何影响生成质量？

**回答：**

**Temperature（温度）：**

控制生成文本的随机性。

- **低Temperature（0.1-0.3）**：
  - 更确定、更保守
  - 选择概率最高的词
  - 适合：代码生成、事实性回答
  - 缺点：可能重复、缺乏创造性

- **高Temperature（0.7-1.0）**：
  - 更随机、更有创造性
  - 更多样化的输出
  - 适合：创意写作、头脑风暴
  - 缺点：可能不准确、偏离主题

- **推荐值**：
  - 技术问答：0.1-0.3
  - 创意写作：0.7-1.0
  - 一般对话：0.5-0.7

**Top-K：**

只从概率最高的K个词中选择。

```python
# 示例：Top-K = 3
概率分布：
"Spring"：0.4
"Java"：0.3
"Python"：0.15
"Go"：0.1
"其他"：0.05

Top-K=3：只考虑["Spring", "Java", "Python"]
```

- **低Top-K（10-20）**：更保守，只考虑最可能的词
- **高Top-K（50-100）**：更多样化，但可能选择不相关的词
- **推荐值**：40-50

**Top-P（Nucleus Sampling）：**

只从累积概率达到P的词中选择。

```python
# 示例：Top-P = 0.9
概率分布（排序后）：
"Spring"：0.4  (累积：0.4)
"Java"：0.3    (累积：0.7)
"Python"：0.15 (累积：0.85)
"Go"：0.1      (累积：0.95) ← 超过0.9，停止
"其他"：0.05

Top-P=0.9：只考虑["Spring", "Java", "Python"]
```

- **低Top-P（0.5-0.7）**：更保守
- **高Top-P（0.9-0.95）**：更多样化
- **推荐值**：0.9

**组合使用：**

```java
ChatOptions options = ChatOptions.builder()
    .withTemperature(0.3)  // 低温度，更确定
    .withTopK(40)          // Top-K采样
    .withTopP(0.9)        // Top-P采样
    .build();
```

**实际应用：**

**技术面试提问（本项目）：**
```java
// 需要准确、不重复
Temperature: 0.2
Top-K: 30
Top-P: 0.8
```

**创意写作：**
```java
// 需要多样性、创造性
Temperature: 0.8
Top-K: 50
Top-P: 0.95
```

### Q9.5: 什么是Embedding？它在RAG中的作用是什么？

**回答：**

**Embedding（嵌入）：**

将文本转换为固定长度的向量（数字数组），使得语义相似的文本向量距离近。

**示例：**
```
"Spring Boot" → [0.1, 0.3, -0.2, ..., 0.5]  (768维向量)
"Java框架"    → [0.12, 0.28, -0.18, ..., 0.48]  (相似向量)
"Python"      → [-0.3, 0.1, 0.4, ..., -0.2]  (不同向量)
```

**在RAG中的作用：**

**1. 文档向量化：**
```java
// 将文档切分为chunks
List<Document> chunks = splitDocument(doc);

// 对每个chunk生成Embedding
for (Document chunk : chunks) {
    float[] embedding = embeddingModel.embed(chunk.getText());
    chunk.setEmbedding(embedding);
    
    // 存储到向量数据库
    vectorStore.add(chunk);
}
```

**2. 查询向量化：**
```java
// 将用户问题转换为向量
String query = "Spring Boot的自动配置原理是什么？";
float[] queryEmbedding = embeddingModel.embed(query);
```

**3. 相似度检索：**
```java
// 计算查询向量与文档向量的相似度
// 使用余弦相似度（Cosine Similarity）
double similarity = cosineSimilarity(queryEmbedding, docEmbedding);

// 检索topK最相似的文档
List<Document> results = vectorStore.similaritySearch(
    SearchRequest.builder()
        .query(query)
        .topK(3)
        .build()
);
```

**相似度计算：**

**余弦相似度（Cosine Similarity）：**
```
similarity = (A · B) / (||A|| × ||B||)

范围：[-1, 1]
1：完全相同
0：无关
-1：完全相反
```

**项目中的Embedding模型：**

```java
// 使用Spring AI的Embedding模型
@Autowired
private EmbeddingModel embeddingModel;

// 生成Embedding
List<Double> embedding = embeddingModel.embed("Spring Boot");
```

**常见Embedding模型：**
- **OpenAI**：text-embedding-ada-002
- **阿里云**：text-embedding-v1
- **智谱AI**：text-embedding-3-large
- **开源**：BGE、M3E等

**优化方向：**

1. **选择合适的模型**：根据语言（中英文）选择
2. **Chunk大小**：通常256-512 tokens
3. **Chunk重叠**：10-20%重叠，避免信息丢失
4. **元数据过滤**：结合向量检索和元数据过滤

### Q9.6: 什么是幻觉（Hallucination）？如何减少幻觉？

**回答：**

**幻觉（Hallucination）：**

1. **训练数据错误**：模型学习了错误信息
2. **知识截止**：模型训练数据有截止日期
3. **推理错误**：模型逻辑推理出错
4. **缺乏事实依据**：模型"编造"信息

**减少幻觉的方法：**

**1. RAG（检索增强生成）：**
```java

**3. 事实核查：**

**4. 温度参数调整：**

**5. Few-Shot Learning：**

### Q10.2: Redis作为向量数据库的实现原理？

**回答：**

**Redis向量存储：**

**1. 数据结构：**
```java
// 使用Redis Hash存储向量
Key: "vector:doc:123"
Fields:
  - "id": "doc123"
  - "text": "Spring Boot文档内容"
  - "embedding": "[0.1,0.2,...]"  // JSON格式的向量数组
  - "metadata": "{\"doc_type\":\"scoring_criteria\"}"
```

**2. 相似度检索：**
```java
// Redis使用KNN（K-Nearest Neighbors）算法
// 1. 计算查询向量与所有文档向量的距离
// 2. 排序，返回topK

// Spring AI RedisVectorStore实现
public List<Document> similaritySearch(SearchRequest request) {
    // 1. 获取查询向量
    float[] queryVector = embeddingModel.embed(request.getQuery());
    
    // 2. 检索所有文档
    Set<String> keys = redisTemplate.keys("vector:doc:*");
    
    // 3. 计算相似度并排序
    List<ScoredDocument> scoredDocs = keys.stream()
        .map(key -> {
            float[] docVector = getVector(key);
            double score = cosineSimilarity(queryVector, docVector);
            return new ScoredDocument(key, score);
        })
        .sorted(Comparator.comparing(ScoredDocument::getScore).reversed())
        .limit(request.getTopK())
        .collect(Collectors.toList());
    
    // 4. 返回文档
    return scoredDocs.stream()
        .map(doc -> getDocument(doc.getKey()))
        .collect(Collectors.toList());
}
```

**3. 性能优化：**
- **索引**：可以建立向量索引（如HNSW）
- **分片**：大规模数据可以分片存储
- **缓存**：常用查询结果缓存

**4. 限制：**
- 内存容量限制
- 大规模检索性能不如专业向量数据库

### Q10.4: 虚拟线程（Virtual Threads）的原理和优势？

**回答：**

**虚拟线程原理：**

**1. 平台线程（Platform Thread）vs 虚拟线程（Virtual Thread）：**

| 特性 | 平台线程 | 虚拟线程 |
|------|----------|----------|
| **实现** | OS线程（1:1映射） | JVM管理的轻量级线程 |
| **内存** | ~1MB栈空间 | 几KB |
| **创建成本** | 高 | 低 |
| **数量限制** | 数千个 | 数百万个 |
| **调度** | OS调度 | JVM调度（M:N映射） |

**2. 工作原理：**
```
平台线程（载体线程）
  ├─ 虚拟线程1（运行中）
  ├─ 虚拟线程2（阻塞，挂载到其他载体线程）
  └─ 虚拟线程3（运行中）

当虚拟线程阻塞时（如IO操作）：
- 虚拟线程从载体线程卸载
- 载体线程可以运行其他虚拟线程
- 阻塞完成后，虚拟线程可以挂载到任何可用的载体线程
```

**3. 优势：**

**a) 高并发：**
```java
// 可以创建百万级虚拟线程
for (int i = 0; i < 1_000_000; i++) {
    Thread.ofVirtual().start(() -> {
        // IO操作
        httpClient.send(request);
    });
}
```

**b) 简化代码：**
```java
// 无需线程池，直接创建
Thread.ofVirtual().start(() -> {
    // 任务逻辑
});

// 或使用Executor
Executor executor = Executors.newVirtualThreadPerTaskExecutor();
executor.execute(() -> {
    // 任务逻辑
});
```

**c) 适合IO密集型：**
- 虚拟线程在IO阻塞时会自动释放CPU
- 适合：HTTP请求、数据库查询、文件IO

**4. 注意事项：**

**不适合CPU密集型：**
```java
// ❌ 不适合：CPU密集型任务
Thread.ofVirtual().start(() -> {
    for (int i = 0; i < 1_000_000; i++) {
        // 大量计算
        Math.sqrt(i);
    }
});
```

**线程本地变量：**
```java
// 虚拟线程支持ThreadLocal
ThreadLocal<String> local = new ThreadLocal<>();
Thread.ofVirtual().start(() -> {
    local.set("value");
    // ...
});
```

**项目中的应用：**
- 并行评估多道面试题
- AI API调用（IO密集型）
- 性能提升82%

**回答：**

**消息确认机制：**

**1. 自动确认（Auto Ack）：**

@RabbitListener(queues = "queue")

    // 处理消息
    // 如果方法正常返回，自动确认
    // 如果抛出异常，消息会重新入队
}
```

**2. 手动确认（Manual Ack）：**
```java
@RabbitListener(queues = "queue")
public void handle(Message message, Channel channel) throws IOException {
    try {
        // 处理消息
        processMessage(message);
        
        // 手动确认
        channel.basicAck(message.getMessageProperties().getDeliveryTag(), false);
    } catch (Exception e) {
        // 拒绝消息，不重新入队（发送到DLQ）
        channel.basicNack(
            message.getMessageProperties().getDeliveryTag(),
            false,  // 不批量拒绝
            false   // 不重新入队
        );
    }
}
```
